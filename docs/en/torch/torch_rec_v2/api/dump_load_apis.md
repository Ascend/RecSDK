# Saving and Loading APIs

## `DynamicEmbDump`

**Description**

Automatically detects dynamic embedding tables in a Torch model and dumps them in parallel to the file system, ultimately producing a single file.

**Function Prototype**

```python
def DynamicEmbDump(
    path: str,
    model: nn.Module,
    table_names: Optional[Dict[str, List[str]]] = None,
    optim: Optional[bool] = False,
    pg: dist.ProcessGroup = dist.group.WORLD,
    allow_overwrite: bool = False,
)
```

**Parameters**

|Parameter|Type|Mandatory/Optional|Description|
|--|--|--|---|
|path|str|Mandatory|Main directory path for saving files.|
|model|nn.Module|Mandatory|Model object that contains dynamic embedding tables.|
|table_names|Optional[Dict[str, List[str]]]|Optional|Embedding collection names to export and the corresponding lists of dynamic embedding tables. If the value is `None`, all dynamic embedding tables are exported.|
|optim|Optional[bool]|Optional|Indicates whether to save the optimizer state. The default value is `False`.|
|pg|dist.ProcessGroup|Optional|Process group used to control the communication scope during export. The default is the global `WORLD` group.|
|allow_overwrite|bool|Optional|Indicates whether to overwrite an existing folder. The default value is `False`.|

**Example**

```python
from dynamic_emb.distributed.dump_load import DynamicEmbDump
DynamicEmbDump(
    path=path,
    model=model,
    optim=True,
    allow_overwrite=True
)
```

**References**

For the call flow and examples of this interface, see [Migration and Training](../migration_and_training.md).

## `set_score`

**Description**

Sets scores for the dynamic embedding tables in a model. You can use the scores to control later processing logic, such as incremental export, that depends on score thresholds.

**Function Prototype**

```python
def set_score(
    model: nn.Module,
    table_score: Union[int, Dict[str, Dict[str, int]]],
) -> None
```

**Parameters**

|Parameter|Type|Mandatory/Optional|Description|
|--|--|--|--|
|model|nn.Module|Mandatory|Model object that contains dynamic embedding tables.|
|table_score|Union[int, Dict[str, Dict[str, int]]]|Mandatory|Score-setting strategy. If an `int` is passed, the system sets the same score for all dynamic embedding tables. If a `Dict[str, Dict[str, int]]` is passed, the outer key is the embedding collection path in the model, the inner key is the table name, and the value is the score.|

**Example**

```python
from dynamic_emb import set_score

# Set the same score for all dynamic embedding tables.
set_score(model, 100)

# Set scores separately by collection and table name.
set_score(
    model,
    {
        "model.embedding": {
            "user_table": 100,
            "item_table": 200,
        }
    },
)
```

## `get_score`

**Description**

Returns the current scores of the dynamic embedding tables in the model as a dictionary organized by embedding collection and table name.

**Function Prototype**

```python
def get_score(
    model: nn.Module,
) -> Optional[Dict[str, Dict[str, int]]]
```

**Parameters**

|Parameter|Type|Mandatory/Optional|Description|
|--|--|--|--|
|model|nn.Module|Mandatory|Model object that contains dynamic embedding tables.|

**Returns**

|Return Value Type|Description|
|--|--|
|Optional[Dict[str, Dict[str, int]]]|Returns the score dictionary on success. If the model contains no dynamic embedding collections or dynamic embedding tables, returns `None` and issues a warning.|

**Example**

```python
from dynamic_emb import get_score

score_info = get_score(model)
if score_info is not None:
    print(score_info)
```

## `DynamicEmbLoad`

**Description**

Loads data from the binary file generated by `DynamicEmbDump` into the dynamic embedding tables of a Torch model.

**Function Prototype**

```python
def DynamicEmbLoad(
    path: str,
    model: nn.Module,
    table_names: Optional[Dict[str, List[str]]] = None,
    optim: bool = False,
    pg: dist.ProcessGroup = dist.group.WORLD,
):
```

**Parameters**

|Parameter|Type|Mandatory/Optional|Description|
|--|--|--|--|
|path|str|Mandatory|Main directory path for loading files.|
|model|nn.Module|Mandatory|Model object that contains dynamic embedding tables.|
|table_names|Optional[Dict[str, List[str]]]|Optional|Embedding collection names to load and the corresponding lists of dynamic embedding tables. If the value is `None`, all dynamic embedding tables that are found are loaded.|
|optim|Optional[bool]|Optional|Indicates whether to load the optimizer state. The default value is `False`.|
|pg|dist.ProcessGroup|Optional|Process group used to control the communication scope during loading. The default is the global `WORLD` group.|

**Example**

```python
from dynamic_emb.distributed.dump_load import DynamicEmbLoad
DynamicEmbLoad(
    path=path,
    model=model,
    optim=True
)
```

**References**

For the call flow and examples of this interface, see [Migration and Training](../migration_and_training.md).

## `incremental_dump`

**Description**

Incrementally exports eligible index-embedding key-value pairs from the dynamic embedding tables in a model based on the score threshold. It exports only the entries whose **score is greater than or equal to the threshold** and returns the exported keys, values, and the current score of each table for the next incremental export or `set_score`.

The interface automatically detects `ShardedDynamicEmbeddingCollection` in the model. In distributed scenarios, you can use `pg` to specify the communication process group. In multi-GPU scenarios, the matching results on each rank's local shard are aggregated through collective communication and then returned.

**Function Prototype**

```python
def incremental_dump(
    model: nn.Module,
    score_threshold: Union[int, Dict[str, Dict[str, int]]],
    pg: Optional[dist.ProcessGroup] = None,
) -> Union[
    Tuple[
        Dict[str, Dict[str, Tuple[torch.Tensor, torch.Tensor]]],
        Dict[str, Dict[str, int]],
    ],
    None,
]:
```

**Parameters**

|Parameter|Type|Mandatory/Optional|Description|
|--|--|--|--|
|model|nn.Module|Mandatory|Torch model object that contains dynamic embedding tables, usually a model wrapped by `DistributedModelParallel`.|
|score_threshold|Union[int, Dict[str, Dict[str, int]]]|Mandatory|Score threshold strategy. When an `int` is passed, the system uses that threshold for incremental export of all dynamic embedding tables in the model. When a `Dict[str, Dict[str, int]]` is passed, the outer key is the path of the embedding collection in the model (`module_path`), the inner key is the dynamic embedding table name, and the value is the score threshold of that table. The system exports only the tables that appear in the dictionary.|
|pg|Optional[dist.ProcessGroup]|Optional|Process group used to control the communication scope during incremental export. The default value is `None`. In distributed training when `world_size` is greater than 1, it is used to aggregate matching results across ranks.|

**Returns**

|Return Value Type|Description|
|--|--|
|Tuple[Dict, Dict]|On success, returns the tuple `(ret_tensors, ret_scores)`. `ret_tensors[collection_path][table_name]` is `(keys, values)`, where `keys` is the index tensor matched on the host side and `values` is the corresponding embedding. When optimizer state is included, the system flattens it according to the table layout. `ret_scores[collection_path][table_name]` is the current score after export. You can use it as the `score_threshold` input for the next `incremental_dump` call, or write it back to the model through `set_score`. When `score_threshold` is an `int`, `ret_scores` contains the scores of all dynamic embedding tables. When `score_threshold` is a dictionary, `ret_scores` contains only the tables actually exported in this run.|
|None|If the model contains no `ShardedDynamicEmbeddingCollection` or no dynamic embedding tables, the system issues a warning and returns `None`.|

**Exceptions**

|Exception|Description|
|--|--|
|ValueError|Raised when the type or value of `model`, `score_threshold`, or `pg` is invalid. For example, `score_threshold` is neither an `int` nor a `Dict[str, Dict[str, int]]`, or the threshold exceeds the allowed int64 range.|

**Example**

```python
import torch.distributed as dist
from torchrec.distributed.comm import intra_and_cross_node_pg
from dynamic_emb.distributed.incremental_dump import (
    get_score,
    set_score,
    incremental_dump,
)

# 1. Read the current score of each table. This step is optional.
score_info = get_score(model)
assert score_info is not None
prefix_path = "model"  # Embedding collection path in the model.
undump_score = score_info[prefix_path]

# 2. After training for several steps, use the previous score as the threshold for incremental export.
ret_tensors, ret_scores = incremental_dump(
    model,
    {prefix_path: undump_score},
    intra_and_cross_node_pg()[0],
)
undump_score = ret_scores[prefix_path]

# 3. Verification: The indexes accessed in this forward pass should appear in the exported keys.
for table_name, indices in unique_indices_per_table.items():
    dumped_keys = set(ret_tensors[prefix_path][table_name][0].tolist())
    assert indices.issubset(dumped_keys)
```
