二、环境搭建过程
1. HiDevLab 创建环境：算力类型选择「昇腾950PR」，镜像选择「【应用使能】RecSDK」，1 卡。
2. NPU 验证：npu-smi info 正常输出设备信息（Ascend950PR，Health OK，显存 131072 MB）。（附件1）
3. 环境变量配置：
  - 官方文档要求的 source /usr/local/set_cann_env.sh a5 在镜像中不存在，改用 source /usr/local/Ascend/ascend-toolkit/set_env.sh；
  - source /opt/buildtools/torch_v2_pt2.7.1/bin/activate 激活虚拟环境。
4. 环境验证：python -c "import torch; import torch_npu; print(...)" 输出 NPU可用: True，说明设备可被 PyTorch 识别。（附件2）
三、样例运行过程
1. git clone -b develop_examples_and_tools https://gitcode.com/Ascend/RecSDK.git，进入 torch_rec_v2_examples/little_demo。
2. 下载解压 MovieLens-1M 数据集到 ./ml-1m（movies.dat / ratings.dat / users.dat 就位）。（附件4）
3. 执行 bash run.sh，程序在分布式初始化 dist.barrier(device_ids=[local_rank]) 阶段报错退出，未能显示 Demo done.。（附件3）

五、体验总结与建议
- 整体体验：镜像内软件栈预装完整、NPU 识别与基础验证顺畅；但单卡 HCCL 通信初始化失败导致 Little Demo 无法跑通，属平台环境已知问题，个人操作层面已完成全部规定步骤。
- 文档改进建议：
  a. 补充 set_cann_env.sh a5 不存在时的替代命令；
  b. 增加启动训练前的环境自检小节（npu-smi + 单卡 HCCL 最小用例）；
  c. 增加 HCCL error 19 的 FAQ，链接到 Ascend/pytorch#5324，避免重复踩坑；
  d. 将 TorchNPU 版本标注更新为 2.7.1.post4。
- 对 RecSDK Torch 产品的建议：建议尽快修复 HiDevLab 950PR 单卡环境的物理卡映射问题，或在文档显著位置标注该已知限制及临时规避方案，提升 MeetUp 实操体验。
