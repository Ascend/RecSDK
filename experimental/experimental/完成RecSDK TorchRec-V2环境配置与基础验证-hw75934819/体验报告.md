## 4 实际执行步骤

- **任务入口文档**：https://gitcode.com/Ascend/RecSDK/blob/develop/docs/zh/torch/torch_rec_v2/03_quick_start/quick_start.md

### 步骤 1：盘点环境 + 激活虚拟环境 + 验证 NPU 可用

```bash
npu-smi info
export LD_LIBRARY_PATH=/usr/local/python3.11.0/lib:$LD_LIBRARY_PATH
source /usr/local/Ascend/cann/set_env.sh
source /opt/buildtools/torch_v2_pt2.7.1/bin/activate
export LD_LIBRARY_PATH=$(python -c "import site; print(site.getsitepackages()[0])"):$LD_LIBRARY_PATH
python -c "
import torch, torch_npu, dynamic_emb, torchrec
print('torch:', torch.__version__)
print('torch_npu:', torch_npu.__version__)
print('NPU count:', torch.npu.device_count())
print('torchrec:', torchrec.__version__)
print('dynamic_emb: OK')
"
```

- **预期**：所有模块 import 成功，NPU count = 2
- **实际**：成功，输出 `torch: 2.7.1+cpu`, `torch_npu: 2.7.1.post4`, `NPU count: 2`, `torchrec: 1.2.0+npu`, `dynamic_emb: OK`
- **截图**：`05_step1.png`

### 步骤 2：创建一键环境脚本

```bash
cat > /workspace/setup_recsdk_env.sh << 'EOF'
#!/bin/bash
export LD_LIBRARY_PATH=/usr/local/python3.11.0/lib:$LD_LIBRARY_PATH
source /usr/local/Ascend/cann/set_env.sh 2>/dev/null
source /opt/buildtools/torch_v2_pt2.7.1/bin/activate
export LD_LIBRARY_PATH=$(python -c "import site; print(site.getsitepackages()[0])"):$LD_LIBRARY_PATH
export ASCEND_HOME_PATH=${ASCEND_HOME_PATH:-/usr/local/Ascend/cann-9.1.0-beta.3}
EOF
chmod +x /workspace/setup_recsdk_env.sh
source /workspace/setup_recsdk_env.sh
```

- **预期**：后续每个 shell `source setup_recsdk_env.sh` 即可使用
- **实际**：成功，之后所有命令均以此脚本为入口
- **截图**：`06_step2.png`

### 步骤 3：下载样例代码 + 数据集

```bash
cd /workspace
git clone -b develop_examples_and_tools https://gitcode.com/Ascend/RecSDK.git
cd RecSDK/torch_rec_v2_examples/little_demo
wget https://files.grouplens.org/datasets/movielens/ml-1m.zip
unzip ml-1m.zip
wc -l ml-1m/ratings.dat   # 应为 1,000,209
```

- **预期**：ratings.dat 1,000,209 行，每行 4 个 `::` 分段
- **实际**：首次下载返回损坏文件（20,497 行只有 3 段，如 `2180::::12428670`），`dataset.py` 解析崩溃；重新 `wget` 后恢复正常
- **截图**：`07_step3.png`

### 步骤 4：运行官方样例（训练）

```bash
source /workspace/setup_recsdk_env.sh
cd /workspace/RecSDK/torch_rec_v2_examples/little_demo
export OMP_NUM_THREADS=4
torchrun --rdzv-backend=c10d --rdzv-endpoint=localhost:6000 \
  --nnodes=1 --nproc-per-node=1 main.py --train
```

- **预期**：训练正常结束，输出 `Demo done.`
- **实际**：成功。Epoch 1/2 Loss 22.88→1.18；Epoch 2/2 Loss 0.98→0.95；Test Loss 1.53；输出 `Demo done.`
- **截图**：`08_step4.png`

### 步骤 5：运行完整链路（训练 + 保存 + 加载 + 推理）

```bash
source /workspace/setup_recsdk_env.sh
torchrun --rdzv-backend=c10d --rdzv-endpoint=localhost:6000 \
  --nnodes=1 --nproc-per-node=1 main.py --train --dump --load
```

- **预期**：DynamicEmbDump / DynamicEmbLoad 正常工作，load 后推理成功
- **实际**：成功。dump 后训练 Epoch 2 Loss 0.9210；load 后推理 Test Loss 1.3117；输出 `Demo done.`
- **截图**：`09_step5.png`

## 8 体验总结

| 维度 | 评价 | 说明 |
| --- | --- | --- |
| 文档易懂度 | 一般 | 快速入门文档的方案 1（镜像启动）路径清晰，但方案 2（手动安装）的依赖矩阵、路径配置细节在 CANN 与 site-packages 处缺失 |
| 流程顺畅度 | 一般 | 从环境可用到 Demo done 约 20 分钟，其中 70% 时间在排 `LD_LIBRARY_PATH` 和数据集损坏问题；PyTorch/TorchNPU/TorchRec 预装是最省力的环节 |
| 报错可读性 | 好 | torch_npu 和 dynamic_emb 的报错基本能定位到根因（.so 找不到），fbgemm fallback CPU 也有明确 warning |
| 整体评价 | 4 / 5 | 样例代码质量高、NPU 算子兼容性好，主要短板在**容器启动脚本的环境变量注入**和**数据完整性校验** |

- **最耗时的一步**：步骤 1 + 步骤 2 —— 诊断并修复 `libpython3.11.so.1.0` 和 `libdynamic_emb_op_npu.so` 两个动态库加载问题，约 15 分钟
- **最值得改进的点**：容器启动时的完整环境初始化脚本。建议在 `/usr/local/set_cann_env.sh` 之外，额外提供 `source /opt/buildtools/torch_v2_pt2.7.1/bin/activate` + site-packages LD_LIBRARY_PATH 固化到 shell rc 文件，让开发者 `docker exec -it container bash` 后直接可用
